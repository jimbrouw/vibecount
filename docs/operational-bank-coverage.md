# Operational review V2: complete bank source context

Migration `20261019110000_operational_bank_coverage.sql` and the current review model extend operational review with complete bank coverage. Foreign admission remains closed. This is not tax/source completeness, readable-byte certification, account valuation or the finished foreign financial workflow.

## Compatibility and source scope

The predecessor SQL catalog is copied to private `financial_review_catalog_v1`. Current catalog/read/capture function identities and ACLs remain unchanged. The original TypeScript parser/provider serializer is retained in `financial-review-v1.ts`; `parseFinancialReview` remains explicit V1 replay. `readFinancialReview` now requires `parseCurrentFinancialReview` and `vibecount.financial-review/2`. Current requests cannot fall back to V1 or omit bank coverage. Historical V1 sample/quarter arithmetic and serialized provider output remain unchanged.

V2 carries complete owner-wide `bank_source_coverage` under the existing exact safe contract. Active operational sources use the selected **cash tax year**, with imports other than discarded, including unavailable import status. Four quarters follow 6 April/July/October/January boundaries. Discarded and other-year observations, and accounts without active year observations, remain owner-wide context; they do not become fictitious year activity. Unlike original units are not summed and retained valuations do not enter recognised GBP ledger totals.

Year and quarter fields include active `source_count`, `unsupported_source_count`, `source_unavailable_count` and `unresolved_source_count`. Unsupported means non-native/invalid representation; unavailable means missing source closure or matching Storage object metadata. These sets overlap. Unresolved is a distinct union with the previous native decision predicate, so foreign Unknown is counted once and foreign Business with null GBP cannot disappear through a materiality expression. Native source-object loss is independently visible even when currency eligibility remains native. SQL derives counts from complete raw observations; TypeScript independently reconciles raw year/quarter partitions and enforces unresolved lower bounds. The model does not claim to recompute every legacy decision predicate from the bounded safe projection.

The V2 SHA-256 stamp binds the legacy financial/invoice stamp, complete owner-wide bank coverage and all new counters. Changing a valuation head or source availability invalidates the operational context even without changing financial effects. The complete response fails above two megabytes; failures are unavailable rather than truncated or zero. Parsed current DTOs retain the V1 `original_pence` output alias for invoice originals; raw `original_minor` remains accepted and conflicting aliases reject.

## Service capture and UI

Quarter capture remains service-only and receives only owner/year/quarter/as-of, never client-supplied totals or status. It obtains the owner reconciliation lock, freezes bank source/valuation dependencies plus transitive invoice credit/refund balance tables, reads current V2 and writes the derived result. Unsupported/unavailable sources force operational attention independently of GBP materiality. No approved activity also requires attention. Even `ok` means only no listed operational issues; source completeness and tax readiness remain unverified.

Three nullable fields are added to the existing latest-check table: quarter unsupported/unavailable counts and complete bank coverage stamp. Old rows/notes/status are untouched by upgrade. A later service capture legitimately replaces the latest row for that quarter; this table is not immutable history and has no request-recovery contract. A version/stamp/as-of mismatch remains historical on the review page.

Quarter cards include active source-only quarters and label GBP figures as recognised ledger totals. The page shows active year counters and owner-wide preserved source context separately. The provider preview shows safe aggregate counts and canonical currency groups before per-request consent. Actual prompts contain no bank IDs, account IDs, hashes, original units, valuation details, raw text, filenames, paths or key IDs. Arbitrary invalid currency text is reduced to the static `invalid` group. Existing request/1 remains appropriate because it already binds the current authoritative stamp; the server reloads V2, rejects stale/failed context and requires consent. Changed context remounts the agent and clears consent/results.
